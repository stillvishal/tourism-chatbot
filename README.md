# Jharkhand Tourism Intelligence – ML Prototype

Footfall prediction, crowd classification, anomaly detection and crowd-aware
recommendations, exposed as a REST API with FastAPI.

> **Data warning:** `data/tourism_data.csv` is **synthetic** (generated by `ml/generate_data.py`).
> Metrics are only meaningful for the demo. Replace the CSV with real visitor records
> (columns: `date,destination,visitors,rainfall_mm,temperature_c`) and retrain.

## Structure
```
tourism_ml/
├── requirements.txt
├── ml/
│   ├── config.py         # destinations, capacities, crowd bands, features
│   ├── features.py       # feature engineering (shared by training + inference)
│   ├── generate_data.py  # synthetic dataset generator
│   └── train.py          # trains RF + GBM, time-based split, saves model
├── app/
│   ├── static/chat.html   # the chat window (single file, no build step)
│   ├── main.py           # FastAPI routes
│   ├── schemas.py        # request/response models (API contract)
│   ├── services/chatbot.py    # intent + date parsing, builds reply + cards
│   └── services/predictor.py  # prediction, crowd, recommend, anomaly logic
├── data/                 # tourism_data.csv
└── models/               # footfall_model.joblib, model_metadata.json
```

## Run
```bash
pip install -r requirements.txt
python -m ml.generate_data     # skip if you have real data
python -m ml.train
uvicorn app.main:app --reload
```
Open http://127.0.0.1:8000/docs for interactive Swagger docs.

## Endpoints
| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | liveness + model loaded |
| GET | `/destinations` | list destinations |
| GET | `/model/info` | metrics, feature importances |
| POST | `/predict` | footfall + crowd level + interval for a date |
| GET | `/forecast/{destination}?start=YYYY-MM-DD&days=7` | multi-day forecast |
| POST | `/recommend` | crowd-aware destination ranking |
| POST | `/anomaly` | flag unusual actual visitor counts |
| POST | `/chat` | chatbot: `{message, context}` -> `{reply, cards[], suggestions[], context}` |
| GET | `/chat-ui` | standalone chat window (HTML page) |

Example:
```bash
curl -X POST localhost:8000/predict -H "Content-Type: application/json" \
  -d '{"destination":"Dassam Falls","date":"2026-08-15"}'
```

## Chatbot (for the web developer)
**Quick start:** open `integration_example.html` - it shows a floating chat button (bottom-right) that opens the chat in a panel.
Copy its `<style>`, `<button>/<div>` and `<script>` into the site and set `CHAT_URL` to wherever this API is hosted.

The chat lives in its own page, so the main site stays simple. Integration is one link/button.

Open it in a popup window from any page:
```html
<button onclick="window.open('http://127.0.0.1:8000/chat-ui','chat','width=420,height=680')">
  Chat with us
</button>
```
Or just link to `/chat-ui` (new tab), or embed: `<iframe src="/chat-ui" width="420" height="680"></iframe>`.

- If the website is hosted on a different origin than the API, set `API_BASE` at the top of the
  `<script>` in `app/static/chat.html` (CORS is already enabled).
- Two engines (the chat header shows which is active):
  - **AI mode** (needs `LLM_PROVIDER` in `.env`): an open-source LLM (Ollama or Groq, both free) understands any wording and calls the ML model as tools.
  - **Basic mode** (no key / AI call fails): the offline rule-based bot (`services/chatbot.py`).
- `/chat` is stateless: the page sends back the `context` it received, so follow-ups like
  "what about tomorrow?" work. Replies contain `cards` (prediction, recommendations, forecast, monthly)
  that the page renders; you can reuse the same JSON in your own UI.

## Enabling AI mode (free)
No extra pip packages are needed. Copy `.env.example` to `.env` and pick one option:

- **Ollama (runs on your PC, free, offline):** install from https://ollama.com, run `ollama pull llama3.1:8b`
  (or `llama3.2:3b` for low-RAM PCs and set `LLM_MODEL`), keep Ollama running, set `LLM_PROVIDER=ollama`.
- **Groq (free tier, needs internet):** make a key at https://console.groq.com, set `LLM_PROVIDER=groq` and `LLM_API_KEY=...`.
- **Other OpenAI-compatible services:** `LLM_PROVIDER=custom` + `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`.

Restart `uvicorn`, then check `http://127.0.0.1:8000/health` -> `"chat_mode": "ai"`.
If the AI call fails at runtime (Ollama not running, bad key, no internet) the reason is printed in the uvicorn
terminal and the chat falls back to Basic mode. Small local models can occasionally pick the wrong tool; bigger
models (Groq's 70B) are more reliable.
